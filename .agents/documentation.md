# Documentation

## Purpose and scope

Keep architecture, schema, releases, migrations, and recovery usable without tribal knowledge.

## Mandatory engineering requirements

Maintain essential package guidance in the root README and agent-only engineering rules in `.agents/`.
Never create or restore a repository-local `docs/` directory, standalone runbooks, architecture pages,
or ADRs. Update the permitted guidance in the same change as behavior. Include prerequisites, exact
working directories, environment variables, risks, verification, rollback/forward recovery, and
ownership. Use fictional Rwandan examples only.

## Forbidden patterns

No stale commands, undocumented public APIs, real customer details, credentials, copied vendor docs,
or claims that unexecuted validation passed.

## Correct example

The root README explains that generated Prisma sources are compiled into the package rather than
generated by `gym-api`.

## Common mistakes

Documenting only the happy path, omitting deployment order, or leaving migration caveats in chat.

## Review checklist

- Links and commands match current files and package scripts.
- Operational failure and recovery paths are present.
